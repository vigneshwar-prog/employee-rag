Lesson 001: BM25 Retriever

Date: 2026-07-24

What It Is

BM25 is a keyword-based retrieval algorithm. It ranks documents by how well their words match the query words.

How It Scores (Simple)

  • Higher score if important query words appear in a document.
  • Higher score for rare words (rare words are more informative).
  • Controls document length so very long text does not always win.

Why It Is Useful

  • Fast and reliable when query words and data words are similar.
  • No embeddings required.
  • Great for exact terms like names, project labels, and technologies.

Limitation

BM25 does not understand meaning like embeddings do. If query uses synonyms not present in data text, BM25 can miss good results.

Interview-Ready One-Liner

BM25 is a lexical ranking function that retrieves documents using keyword relevance, balancing term frequency, inverse document frequency, and length normalization.

Checkpoint Questions

  1. If query and data use different words with same meaning, which works better: BM25 or vector retrieval? Why?
  2. Why should long documents not automatically get higher relevance scores?

Lesson 002: Embedding Model Options for This Project

Date: 2026-07-24

What Is an Embedding Model?

An embedding model converts text into a numeric vector so we can compare meaning using vector similarity search.

Options We Can Use Here

  • text-embedding-3-small (through local gate at localhost:8080): ideal when gate embeddings endpoint is healthy.
  • text-embedding-ada-002 (through local gate): older option if served by the same embeddings endpoint.
  • all-MiniLM-L6-v2 (local sentence-transformers): reliable local option when gate embeddings are unavailable.

Quick Comparison

  • Quality: text-embedding-3-small is usually better than ada-002 for modern retrieval use cases.
  • Operational simplicity: gate-based models are easiest only when the embeddings endpoint works in your environment.
  • Reliability: all-MiniLM-L6-v2 runs locally and avoids dependency on gate embeddings availability.
  • Project fit: with only about 97 rows, all three can work; hybrid retrieval design matters more than tiny embedding differences.

Recommended Choice

Current project decision: use all-MiniLM-L6-v2 as primary because gate embeddings are not working in your setup.

Interview-Ready One-Liner

For this environment, I selected all-MiniLM-L6-v2 because it is stable and local; with a small structured dataset, hybrid retrieval design contributes more to accuracy than switching embedding providers.

Checkpoint Questions

  1. Why is all-MiniLM-L6-v2 a practical choice for your current environment?
  2. If the gate embeddings endpoint starts working later, what benchmark would you run before switching back?
  3. For this dataset, why does hybrid retrieval matter more than changing embedding models?
