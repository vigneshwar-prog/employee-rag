    03 Cross-Cutting Concerns

    🛡️

    Security

    • RBAC — roles → index scopes; deny-by-default.
    • ACL filters — embed allowed_groups[] in payload; filter inside the ANN query.
    • Prompt injection — treat retrieved text as data; delimit, strip instructions, never let context trigger tools.
    • PII — Presidio scrub pre-embed; tokenize; encrypt at rest + in transit.
    • Tenant isolation — namespace or per-tenant collection.
    • Audit — log query, docs served, user, timestamp.
    Rule: a vector store without ACL filtering is a data-leak waiting to be indexed.
    ⚡

    Caching

    Embedding cachehash(text)→vec · ∞ TTL
    Retrieval cachehash(q+filters) · 5–60 m
    Prompt cacheprovider-side prefix
    Semantic cachecos ≥ 0.95 → reuse
    Rerank cache(q, doc_id) pairs
    • Key on everything that changes output: model, version, filters, tenant.
    • Invalidate on re-index or doc version bump.
    • Target 30–60% hit rate; it is the single cheapest latency + cost win.
    cost↓ ≈ hit_rate × (embed + LLM $)
    🧪

    Evaluation

    Recall@Kgold in top-K · >0.90
    Precision@Ksignal/noise · >0.60
    MRR1/rank first hit · >0.75
    NDCG@10graded rank · >0.80
    Faithfulnessgrounded claims · >0.95
    Hallucinationunsupported · <2%
    Answer relevancyLLM judge · >0.85
    • Split retrieval eval from generation eval — debug the right half.
    • 150–300 golden Q/A, human-labeled; block deploys in CI on regression.
    • Tools: RAGAS, TruLens, DeepEval, BEIR.
    👁️

    Observability

    • LangSmith — trace chains, datasets, prompt diffs.
    • Arize Phoenix — embedding drift, cluster explorer.
    • OpenTelemetry — vendor-neutral spans per stage.
    • Prometheus — QPS, p50/p95/p99, cache hit, GPU.
    • Grafana — SLO dashboards + burn-rate alerts.
    Retrieval p95≤ 200 ms
    Rerank p95≤ 300 ms
    LLM TTFT≤ 800 ms
    End-to-end p95≤ 2.5 s
    Log the retrieved doc IDs with every answer — without them, no hallucination is ever debuggable.
    📊

    Scalability

    10M+ vectors
    • Shard by tenant/domain; replicate for read QPS.
    • HNSW M=16–32, efC=200, efSearch tuned per recall SLO.
    • Quantize — int8 / binary + rescoring: 4–32× memory cut.
    • Matryoshka dims — 1536→512 for first pass, full for rerank.
    • Two-stage — cheap ANN wide, expensive rerank narrow.
    • Async + batch embedding; GPU batch the reranker.
    • Blue/green re-index — build new collection, alias-swap.
    • Backpressure — queue depth limits, circuit breakers.
    • Autoscale retriever & reranker independently.
    ⚠️

    Common Pitfalls

    avoid
    • Chunks too large → diluted embeddings; too small → lost context.
    • Pure vector search for exact IDs, codes, names, and numbers.
    • No reranker — top-k is similar, not relevant.
    • Metadata discarded at ingest — unrecoverable later.
    • Mismatched embed model between index and query time.
    • Stale index; no re-embed on document update or model upgrade.
    • Stuffing 50 chunks in → lost-in-the-middle, cost blowup.
    • No citations → unverifiable, untrusted, unshippable.
    • Eyeball "vibes" evaluation instead of a golden set.
    • Treating retrieved text as trusted instructions.
    • Single-region vector DB with no snapshot/restore drill.
    ✅

    Best Practices

    do this
    • Start hybrid (dense + BM25 + RRF) — beats dense-only nearly always.
    • Always rerank: retrieve 50 → rerank → keep 5.
    • Chunk 400–800 tokens, 10–15% overlap, respect headings.
    • Parent-child: embed small, return the parent window.
    • Rewrite / expand the query; HyDE for sparse corpora.
    • Enforce "answer only from context, else say you don't know."
    • Return citations + confidence on every response.
    • Version everything: chunker, embed model, prompt, index.
    • Ship an eval gate in CI before any prompt or model change.
    • Cache aggressively; stream tokens to hide latency.
    • Instrument first — you cannot tune what you cannot see.
